## Give each appended capability one claim its checkbox can honestly assert

When appending follow-up work to an existing PRD, do not bundle unrelated fixes under one capability: a checkbox flips as a unit, so mixed criteria make it read done or not-done dishonestly. Split into one capability per claim, title each by the thing it actually acts on (a feature vs a capability), and use a single term for any component the new text references.
