# Plan: implementer-continuation

**Mechanism first, driver prose second, documents last.** The budget line (T1), the ninth `route` token (T2), its per-attempt cap (T3), the tally rule for a refused continuation (T4) and the partial-work splice (T5) are all `scripts/runstate.sh` behaviour. They land before the prose that tells the implementer (T6) and the driver (T7) to use them. A prompt that names a token or subcommand the script does not yet accept is the failure this order prevents: the driver would improvise a continuation, and what it would most likely improvise is a reviewer dispatch on a red tree. Two rules are inherited from `runstate-write-integrity-gaps` and `loop-driver-run-gaps` and are not restated per task. Every new `scripts/test-runstate.sh` case is mirrored in the block that runs with `jq` and `python3` absent from `PATH`, and must produce the same result there. Every prose pin in `scripts/test-report-conventions.sh` uses content-anchored extraction with a non-empty guard and an `under_ceiling` end-anchor refusal.

**Both of the PRD's deferred decisions were looked at here; one is made and one stays deferred.**
1. **The partial-work block sits between the handoff header and the piped body, under the heading `## Partial work on disk`, delimited by whole-line HTML-comment markers. The budget line sits directly above it.** That keeps the body and the `REQUIRED` block adjacent and in the order ADR 0029 fixed. The driver's two conditional lines stay immediately ahead of the six, the extension lines stay after them, and nothing is inserted between any of them. This is the only placement under which "position and content untouched" needs no argument. The first line, `# <pkt>: <title>`, which `run-digest` parses, is untouched too.
2. **Whether `continue` is honoured from the architect, UX designer or doc-writer stays deferred.** `route` does not know which agent returned a line, and T7 routes `continue` from the implementer's line only.

**The handoff is rewritten in place by splicing, never regenerated.** A continuation or a `fix`/`retry` re-dispatch can follow a decider `retry` whose `amend-handoff` block is already in the file. Re-running `runstate.sh handoff` would rebuild the file and drop that amendment. So T5 adds `runstate.sh refresh-handoff`. It replaces, inserts or removes one marked block, leaves every other byte alone, and reads the packet's scope from the `FILES=`/`BUNDLE_FILES=` lines already in its own `handoff.md`. That is a read of this script's own output, never of `gspec/`. Because the budget line is written by T1 at first dispatch and survives every splice, a continuation or re-attempt handoff carries it without a second code path.

**The two counters use different windows, and T2/T3 keep them apart.** Attempts count `fix`/`retry` routing records since the latest `start` record, and a `continue` record never enters that count. Continuations count `continue` routing records since the later of the latest `start` record and the latest routing record whose action was `attempt`. So each fresh attempt gets a fresh continuation allowance, and a `record-start --continue` never resets either counter.

**File overlap, not logic, is what keeps T1–T5 sequential.** `scripts/runstate.sh` and `scripts/test-runstate.sh` carry all five. **T6** and **T7** are `[P]`. Their files are disjoint from each other and from every other task here, and both depend only on barriers. T8 depends on both and therefore carries no marker.

**Cross-feature overlap.** `dispatch-progress-metrics` also has an open plan, but it depends on this feature and shares only `CLAUDE.md` (its T11, this plan's T8). The other open plan is `escalation-decider`, and its three unchecked tasks collide sharply:

> **T16** rewrites `run-digest`/`run-tally` in `scripts/runstate.sh` and `scripts/test-runstate.sh`, the same functions T4 edits. T4 asserts `DECISIONS` as a **delta** against the same run without the `continue` records, never as an absolute figure, so it holds in either landing order.
> **T17** rewrites the `discard-advance` arm in `skills/run-loop/SKILL.md` §3 step 5 and `agents/loop-driver.md` §Routing, the same sections T7 edits. Land one clear of the other, and have whichever lands second carry the first's clause forward rather than restating the section from memory.
> **T13** edits the intro and Grammar list of `templates/status-line.md`. T6 adds `continue` to the same file. Same file, and possibly the same list, so land them sequentially.

**Reflexivity.** `scripts/runstate.sh` is live mid-run, in the run that edits it. From T2 on, that run's own `route` accepts `continue`, though nothing yet emits it. `agents/implementer.md`, `templates/status-line.md`, `skills/run-loop/SKILL.md` and `agents/loop-driver.md` are read at dispatch, so the first run in which an implementer stops at its budget and is continued is the next `/gaffer:run-loop` after T6 and T7. `CLAUDE.md` reaches the harness next session. No frontmatter or hook registration changes, so no packet needs `session_boundary`.
