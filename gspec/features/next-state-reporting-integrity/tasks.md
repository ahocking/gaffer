# Plan: next-state-reporting-integrity

**Two script tasks land first and side by side; the two guards follow, each after the task that empties its file of the construct.** T1 corrects the adapter's selection path and lands the three-state cases with it; T2 closes the deterministic core's three instances and records the fourth. Neither depends on the other and they touch disjoint files. T3 and T4 are the source-text guards, one per sweep, and each depends on the task that removes the instances its scan would otherwise flag — a guard landed before its fix fails on the very lines this feature exists to remove.

**Each corrected condition becomes a captured value tested for emptiness, and the branch body reuses it.** This settles the PRD's first deferred decision. The filter at both sites is `awk`, not `grep`, so a here-string alone cannot express the test (`awk … <<< "$rows" | grep -q .` still ends in a reader that exits on its first match), and folding the emptiness test into the writer (`awk 'END { exit !n }'`) leaves a pipe whose exit status is the only carrier of the answer under the same `pipefail`. Capturing the filtered rows with `$(printf '%s\n' "$rows" | awk …)` reads to end-of-file, so no reader can close before the writer finishes; the test is then `[ -n "$blocked" ]` on a variable, with no pipe at all. The same captured rows feed the per-feature `BLOCKED=` / `DEFERRED=` lines through the existing formatting `awk`, so each state is filtered once instead of twice and the output is byte-identical: same `REASON=` text, same line forms, same `HINT=`, and `all features complete` exactly when neither captured value is non-empty.

**The three deterministic-core instances are closed, not recorded, because no bound can be written down for any of them.** This settles the second deferred decision by reading each writer's maximum output size. The `add-finding` and `drop-finding` duplicate-id checks write the entire `findings:` block through one `printf`; a real summary measured ~362 bytes, and `findings --stale` already treats `ORCH_FINDINGS_INDEX_MAX_BYTES=4096` — exactly PIPE_BUF, the size up to which a single write is atomic — as the index's expected ceiling, so the block is designed to reach the size at which the single-write argument stops holding. `_id_in_set` is called only by `findings --stale`, over the `--finished` set (every finished packet the caller knows) and the cursor-plus-`pending` set (the remaining backlog); neither has any ceiling. Each has a wrong answer that reaches a caller: `add-finding` admits a second entry under an existing id, `drop-finding` reports `not-found` on an entry that exists (the negation turns the writer's signal exit into a miss), and `--stale` reads a finished packet as `unknown` and withholds an expiry. All three take the here-string form `grep -qxF <pattern> <<< "$value"` — the here-string shape (`grep -qx … <<< …`) already used in `_capability_drift_for` and `cmd_complete_capabilities` in `scripts/gspec-backlog.sh`. A here-string is not a pipeline in the shell's sense: bash finishes supplying the value before `grep` can act on it, so `pipefail` has no second status to report. The only recorded instance is `orphan_packet_tag`, and it is not condition-shaped: its value reaches standard output correctly and its polluted exit status is discarded by `|| true`. It gains a comment and nothing else.

**Observe, then fix, inside one packet.** The second capability requires each new case to be run against the pre-change code and observed to fail, and the plan's rule that every sweep is green after every task forbids landing a red case on its own. So T1 carries both the cases and the fix: the implementer writes the cases, runs them against the unfixed `cmd_next`, records the observed failure count in each case's own comment, then applies the correction and lands green. The fixture size is not a guess: the PRD reproduced the failure at 18,756 bytes over 15 filtered rows and saw none at 733 bytes, so each fixture must produce a filtered payload of at least twice the reproducing size, with the byte size it builds stated in its comment, and the assertion runs in a repeat loop so the pre-fix observation is a count over invocations rather than a single draw. A case sized below the buffer threshold would certify the fix while exercising nothing.

**The guard's shape is exactly the construct, and it is written per sweep.** This settles the third deferred decision. The shape is a non-comment source line containing a single `|` (not `||`) followed by `grep` carrying `q` in its flag cluster — the pipe-fed `grep -q` this whole feature is about. Value-producing `| head -1 | … || true` pipelines are outside the shape by the PRD's own definition (their final stage is not a condition), which is why `orphan_packet_tag` is documented in T2 rather than listed as an exception. The two guards are written per sweep rather than shared: `scripts/test-gspec-backlog.sh` and `scripts/test-runstate.sh` source nothing in common and each runs standalone in CI, and this repo's stated precedent is to reimplement a small helper rather than add a file two sweeps depend on (`scripts/migrate.sh`'s `_findings_index_block_bytes` says so in its own comment). Each guard carries its exception list as a literal in the case — one entry per instance, the line fragment and the reason it is safe — and fails on any hit outside it. After T1 and T2 both lists are empty, deliberately: the empty list is the record, and the case comment says so and says how to add to it. Each guard also proves itself: it copies the file it scans to a temp path, injects an instance inside a function body and another at the end, runs the same scan, and asserts exactly those lines are flagged — so the implementation-time demonstration the PRD asks for is also a standing assertion.

**Every script task names its sweep case.** T1 names `scripts/test-gspec-backlog.sh`; T2 names `scripts/test-runstate.sh`; T3 and T4 are themselves sweep cases.

**File contention, and why all four tasks are `[P]`.**
- `scripts/gspec-backlog.sh` is T1's alone; `scripts/runstate.sh` is T2's alone.
- `scripts/test-gspec-backlog.sh` is edited by T1 and T3; `scripts/test-runstate.sh` by T2 and T4.

T1 and T2 have no deps and disjoint files. T3 (`deps: T1`) and T4 (`deps: T2`) sit in the wave after them, with deps strictly backward and files disjoint from each other. T3 shares a file with T1 and T4 with T2, but never within one wave.

**`gspec-adapter-consistency` must not be in flight against T1 or T3.** It refactors this adapter's shared pattern blocks and adds cases to the same sweep, and its own scope forbids the reporting change made here. No logical dependency either way; it has no plan today.

**Reflexivity.** `scripts/*.sh` take effect mid-run, in the run that edits them. The run that lands T1 was itself started on a `next` answer from the unfixed adapter, and its own end-of-run termination check will call the corrected one — so that run's stop report is the first output under the new contract. No task touches `hooks/hooks.json`, a settings file, or any agent's or skill's frontmatter, so no packet here owes a session boundary.

Every regression sweep must pass green after every task.
