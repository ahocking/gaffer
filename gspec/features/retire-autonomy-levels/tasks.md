# Plan: retire-autonomy-levels

**The guard and its sweep are ONE task, and it is first.** `hooks/guard.sh` is a hook *body*: it takes effect on the next matching tool call, in the run that edits it (CLAUDE.md, reflexivity). A packet that removed the level branch and left `scripts/test-guard.sh` for a later packet would run the rest of the feature against an unpinned guard, and the second success metric — the kept-case count — would have no baseline to compare against once the file had already moved. So T1 carries the policy change, the resolver deletion, and the whole case surgery together. Everything after it is prose, config, or a different script, and none of it can re-open a git gate.

**The fixed rule set is expressed as DELETION, not as a constant.** `ORCH_AUTONOMY_DEFAULT`, `autonomy_rank`, `read_autonomy_file`, `read_autonomy_ceiling`, `resolve_autonomy`, `ensure_autonomy`/`_AUTONOMY_RESOLVED` and the four rank comparisons inside `check_commit_policy`/`check_merge_policy`/`check_rebase_policy`/`check_push_policy` all go, rather than staying in place with the level pinned to `full-autonomy`. Two reasons, and the first is the metric: a resolver nothing reads still *names* `interactive`, `supervised` and `autonomous`, so `hooks/guard.sh` would still count against "No level left to offer" while doing nothing. The second is that a constant is an invitation — a branch with one live arm is how the four levels come back a release later.

**Two `test-guard.sh` cases CONVERT rather than drop, and that is the point of the second metric.** The PRD's drop rule is mechanical, and applied literally it would take two cases whose real subject is not the level: the merge-precision case that pins a *real* `git merge` still routing into the soft gate (it currently proves routing by observing the level denial, and with no level it would allow for the wrong reason — re-point it at a merge into `main`, which the branch rule still denies), and the foreign-`CLAUDE_PROJECT_DIR` case that pins "a foreign config root can never LOOSEN the cwd project" (the only case in the sweep for that direction — re-express it against `bypass-ask-tier`, which resolves restrictively the same way). Everything else on the drop list below is genuinely level-only. The nested-checkout-on-`main` case is the opposite trap and is **kept**: its `.agents/autonomy` file is only scaffolding, and its denial comes from the branch.

**Baselines, measured on this plan's starting commit.** *"No level left to offer"*: **23 shipped files** trip the first metric — `hooks/guard.sh`, `hooks/session-start.sh`, `scripts/test-guard.sh`, `scripts/metrics.sh`, `scripts/test-metrics.sh`, `scripts/test-report-conventions.sh`, `skills/set-autonomy/SKILL.md`, `skills/run-loop/SKILL.md`, `skills/resume/SKILL.md`, `agents/chief-engineer.md`, `agents/architect.md`, `agents/implementer.md`, `templates/report-templates.md`, `templates/task-packet.yaml`, `templates/spec-driven-base/CLAUDE.md`, `templates/spec-driven-base/spec-setup.md`, `templates/spec-driven-base/.agents/project-overrides.yaml`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `README.md`, `CONTRIBUTING.md`, `CLAUDE.md`, `SECURITY.md`. `agents/loop-driver.md` is a 24th borderline file — it names no level control but conditions the merge step on `full-autonomy`, so it is cleaned anyway. Files that match the survey grep and are **not** in the count, because there the word is not a level: an interactive UI, an interactive installer prompt, "passed interactively" (`agents/ux-designer.md` is one), and **the phrase "guided autonomy loop", which is the loop's own name** in the `run-loop`, `resume`, `pause` and `metrics` skill descriptions and stays everywhere — one ruling for all four files. `scripts/migrate.sh` and `skills/migrate/SKILL.md` match and are excluded by the metric as the migrate path. The first survey missed three of the twenty-three; the release check must re-run the grep over the whole shipped tree against the metric's definition rather than trust this list. *"Guard cases survive"*: record `scripts/test-guard.sh`'s printed `passed:` total **before** editing it; the kept count is that total minus the 18 dropped cases T1 enumerates (the two converted cases stay in the count).

**Deferred decision resolved: how a collected run knows the fixed rules were in force.** The PRD requires `full-autonomy` for a window starting after this plugin is installed and `unknown` for one starting before, without reading `ORCH_AUTONOMY` or `.agents/autonomy` — so something the *new* collector emits has to distinguish them, and nothing on an old event line does. The marker is a per-session sentinel file written by `hooks/metrics-log.sh` beside the skill-state file it already maintains (`<events>/_state/<session>.fixed-rules`), and `metrics.sh collect` reads `full-autonomy` only when **every** session in the window carries one, `unknown` otherwise. Rejected: stamping a constant onto every event line (~17% growth on a ~150-byte line, for one bit that never varies within a session), and keying off an install timestamp written by `/gaffer:migrate` (a repo that never migrates would read `unknown` forever). Restrictive rather than "any session", matching how the guard resolves every other cross-root question in this plugin.

**`skills/pause/SKILL.md` carries no level branch — verify and leave it alone.** Capability 2 names `pause` alongside `run-loop` and `resume`; a survey of the shipped tree finds the level branch only in the latter two. Pause's description carries only the "guided autonomy loop" name ruled above as not a level. That is a no-op to confirm, never a cue to go find something to change.

**File contention, and why five tasks are `[P]`.** T1 alone writes `hooks/guard.sh` and `scripts/test-guard.sh`. T2, T3, T4 and T6 are pairwise file-disjoint with backward deps; T5 joins them one wave later, after T4; T7 (`.agents/` config in this very repo) and T8 (the closing docs task) are not marked, because mutating the live checkout's own config and describing the finished state are both things to do alone. `.agents/task-files.yaml` carries no entry for this feature, so every packet resolves to empty scope and runs serialized regardless — the markers are advisory here and nothing schedules on them.

**Reflexivity, per surface.** `hooks/guard.sh` is live on the next tool call in the same run (T1). `scripts/*.sh` take effect the moment they are next run, inside the run that edits them (T1, T5, T6). `agents/*.md` and `skills/*/SKILL.md` are read at dispatch, so T2/T3 land for the *next* dispatch, not the current one. No task touches `hooks/hooks.json` or any settings file, so no packet needs a session boundary. T7 deletes this repo's own `.agents/autonomy`, which is safe only because T1 already made the guard stop reading it — hence the dependency.

**The PRD's `thin-loop-driver` dependency line is stale.** That feature has shipped; the relationship is one-directional and nothing in this plan waits on it. `retire-unused-loop-modes` has also landed, so the parallel-mode and rate-limit files that once referenced levels are already gone and no task here has to account for them.

**Budget note.** Capability 2 carries five tasks against the ≤3 guidance. The level surface it describes spans twenty-three shipped files across the guard, its sweep, three skills, four agents, six templates, two manifests and the repo's own docs; collapsing it further produces packets whose diffs no reviewer can hold in one pass. Stated rather than hidden.

Every regression sweep must pass after every task, and `claude plugin validate .` must stay clean.
